## 1. 一句话定位

> **CogniRead 不是「帮你读完一本书」的工具，而是一面照出你思维盲区的镜子：它用苏格拉底式对话逼你把「以为懂了」变成「真的懂了」。**

一句话定义（对用户）：「一个会追问、会复习、会记住你的 AI 学习伙伴。」

### 2.2 当前能力（v0.2.1）

**内容**：《思考，快与慢》单本课程，4 章 9 个概念，概念间前置依赖解锁。

**教学引擎**（双轨）：
- **本地引擎**（零配置可用）：关键词评估回答 → 4 档分层引导；每阶段答对 2 次推进。
- **AI 引擎**（用户自配 API）：任意 OpenAI 兼容接口（OpenAI / DeepSeek / 智谱 / Ollama / 自定义），SSE 流式输出，System Prompt 内置七大认知框架 + 交互协议（绝不自言自语、绝不连续发言、先提问后展开）。

**学习科学机制**：四阶段认知流程（理解→应用→复习→创造，基于布鲁姆分类法）；艾宾浩斯间隔复习调度（1/3/7/14/30 天）；思维碰撞模式（多视角挑战）。

**系统**：用户画像 + 学习笔记 + 知识联想（localStorage 持久化）；引擎快照恢复（对话中断后可回到原题）；真实活跃度热力图；明暗主题；学习进度可视化（章节树 / 雷达图 / 框架追踪 / 因果链）。

### 2.3 v0.2.1 已修复的问题（摘要）

1. **严重**：AI 模式下当前用户输入从未被发送给模型（只发了历史消息）——AI 对话此前实质不可用。
2. 主题切换（暗色模式）对 Tailwind v4 无效，缺 `@custom-variant dark` 声明。
3. 认知雷达图数据点/连线使用 Tailwind 类名当 SVG 色值，图形渲染为黑色默认色。
4. AI 流式输出时框架激活检测逐字触发，激活度被放大数十倍。
5. 老用户每次打开应用都会重放「新章节解锁」动画。
6. 切换概念后返回时，对话记录恢复了但引擎进度（题号/答对数/阶段计数）从头开始，答题主谓错位。
7. 「学习次数」每次保存进度都 +1，数字严重虚高；热力图是随机假数据 → 改为真实每日互动记录。
8. 思维碰撞本地回退使用闭包旧值 `inputValue` 而非入参。
9. 切换 AI 提供商后模型 ID 不重置，导致模型与接口不匹配。
10. 工程缺失：无 package.json / vite / tsconfig / index.html，项目不可构建 → 全部补齐（Tailwind v4 + Vite 6 + TS 5.7）。
11. `data/bookData.js`（编译产物）会遮蔽 `bookData.ts` 源码（Vite 解析 `.js` 优先）→ 已删除。
12. 若干动态拼接的 Tailwind 类名（空状态卡片、框架卡片）在构建产物中不存在 → 改为字面量。
13. AI 出错回退本地时若流式已开始，输入框内容恢复逻辑不完整。
14. 消息流式输出时聊天区不自动滚动。

完整清单与验收标准见 `docs/ACCEPTANCE.md`。

### 2.4 遗留问题（本版未修，列入后续排期）

- **AI 模式不推进学习进度**：目前掌握判定只在本地引擎生效，AI 模式聊得再好也不会解锁下一概念（见 P1-2）。
- 引导问题里的 `followUpQuestion` 字段从未被真正使用（引擎走到下一题时取的是下一题的问题文本）。
- 学习笔记（`memory.ts` 的 learningNotes）只有存储没有生成入口，AI 从不写学习笔记。
- 复习调度（storage.ts）已实现但无任何 UI 触发复习。
- `OPENCLAW_MEMORY_DATA` 为硬编码的虚构画像数据，应改为首次使用引导用户自填。

## 3. 战略决策：首页改为「一个对话框」

### 3.1 提议

> 把一个智能体嵌入产品，首页只有一个对话框；对话即入口，其他功能不变。

### 3.2 三个视角的评估

**乔布斯视角（聚焦与一句话定义）**——「Focus 意味着对一百个好主意说不。」CogniRead 现在的首页是三栏 + 三个右面板 + 四个设置标签页，功能密度远超一个尚无用户的产品该有的复杂度。一个对话框是这个产品一直在追求的东西（苏格拉底对话）的自然形态：**产品最核心的体验本来就是对话，现在只是让界面和灵魂一致**。但要警惕：对话不是万能入口，复习提醒、进度激励这类「系统该主动找你」的信息，塞进对话流里就是倒退——iPod 的轮盘之所以伟大，是因为它把复杂藏在了正确的层。

**纳瓦尔视角（杠杆与特定知识）**——先重新定义「对话框产品」：如果你的对话框和 ChatGPT 没有区别，你就是在和 OpenAI 竞争，而竞争是模仿的证据。你的特定知识不在对话框，而在**对话框背后那套课程引擎**：苏格拉底分层引导、四阶段推进、间隔重复、概念解锁链——这些是 ChatGPT 裸聊没有的结构。所以正确的问题不是「要不要一个对话框」，而是「对话框是否让我那套引擎更容易被感知」。杠杆判断：代码杠杆（引擎）已经有了，缺的是让杠杆复利的分发面——一个极简的对话首页恰恰是最容易讲清楚、最容易传播的入口（「它会追问你，直到你真的懂」）。这是加分项。

**Ilya 视角（压缩与学习）**——预训练模型是压缩器；学习是人类自己的压缩过程：把大量例证压成一个可复用的模型。对话框是正确的入口，因为**提问就是压缩的相反操作**——它逼你展开自己的模型，暴露它的洞。一个只回答问题的对话框是查表；一个拒绝直接给答案、持续追问的对话框才是教学。关键是：智能体的行为必须由课程引擎约束（阶段、阈值、评估），而不是靠 prompt 祈祷。用结构化输出让 AI 返回 `{level, missingPoints, nextAction}`，UI 才有确定性的东西可以渲染。纯 prompt 的自由聊天是不可测试的，不可测试就没法迭代。

### 3.3 认知科学视角（本产品的立身之本）

- **认知负荷理论**：三栏界面在第一次使用时产生大量外在认知负荷（用户要理解章节树、模式切换、右面板），恰恰挤占了学习本身需要的内在负荷。单对话框把首次认知负荷降到最低。
- **生成效应 + 苏格拉底法的本质**：这个产品的价值全部来自「用户输出」而非「界面展示」。界面越少，输出占比越高。
- **但结构不能消失，只能退到幕后**：学习路径（章节、阶段、复习）是脚手架，完全隐藏会让学习失去方向感和进度激励（目标梯度效应）。正确形态是：**对话在前，结构以「卡片」形式在对话流中按需浮现**——AI 说「你已掌握系统1」时，消息流里出现一张进度卡；复习到期时，对话以一张复习卡开场。

### 3.4 决策

**采纳，定义为 v0.3 的核心目标**，附加三条约束：

1. **不是砍掉结构，是反转主从**：对话是入口和主线；章节树/仪表盘退化为对话中可唤起的卡片与侧边抽屉。
2. **智能体 = 课程引擎的对话外壳，不是通用聊天**：AI 每次回复必须携带结构化判定（理解等级、缺失要点、是否推进阶段），引擎规则（阶段阈值、解锁链、复习调度）保持为代码而非 prompt。
3. **零配置优先**：未配置 API Key 时，首页对话框直接用本地引擎对话（现状能力），而不是摆一个「请先配置」的墙。

## 4. 目标用户与核心场景

**目标用户**：读非虚构硬书（认知科学/经济学/哲学）读到「每个字都认识、合上书全忘」的自学者；备考需要真理解而非背诵的学生。

**核心场景**：
1. **自由进入**（新）：用户打开首页，直接问「什么是锚定效应？」→ 智能体不直接解释，反问「你买东西时有没有被『原价999现价499』影响过？」→ 进入苏格拉底流程。
2. **推进学习**（已有）：对话中答题 → 分层引导 → 四阶段推进 → 解锁下一概念。
3. **到期复习**（改造）：打开首页，智能体主动开场「『损失厌恶』昨天该复习了，你还记得它的量化结论吗？」。
4. **思维碰撞**（已有）：掌握后自由辩论，AI 持续挑战观点。

## 5. 功能规划

### P0 · v0.3 「Agent 首页」（下一个交付）

| # | 功能 | 说明 | 验收要点 |
|---|---|---|---|
| P0-1 | 对话首页 | 首屏 = 标题 + 单输入框 + 欢迎语；原有三栏界面降级为对话内可唤起的抽屉 | 新用户 3 秒内可发出第一句话 |
| P0-2 | 意图路由 | 识别四类输入：概念学习 / 自由提问 / 复习请求 / 闲聊，路由到对应引擎（苏格拉底 / 碰撞 / 复习 / 自由对话） | 本地引擎用规则路由，AI 模式用一次结构化分类调用 |
| P0-3 | 学习卡片流 | 概念卡、阶段推进卡、掌握卡、复习卡以卡片组件嵌入消息流 | 卡片可点击跳转对应状态 |
| P0-4 | 主动开场 | 会话开始时，智能体根据记忆系统主动开口：到期复习 > 未完成概念 > 新概念推荐 | 无 API 时用模板开场 |
| P0-5 | 零配置回退 | 未配置 API 时对话框直接可用（本地引擎），并在卡片中提示「配置 AI 后体验升级」 | 空Key状态完成一次完整四阶段流程 |

### P1 · v0.4 「智能教学闭环」

| # | 功能 | 说明 |
|---|---|---|
| P1-1 | AI 结构化评估 | AI 回复要求 JSON 双段输出（正文 + `{level, matchedPoints, missingPoints, stageAction}`），UI 渲染正文，引擎消费判定 → AI 模式真正推进四阶段 |
| P1-2 | 掌握判定统一 | 本地/AI 双轨产出同一套进度事件，解锁、复习调度共用 |
| P1-3 | 自动学习笔记 | 概念掌握时 AI 生成 summary + keyPoints 写入 learningNotes，复习时取用 |
| P1-4 | 复习 UI | 仪表盘「待复习」清单 + 对话开场复习卡，完成复习调用 `recordReview` |
| P1-5 | 真实画像引导 | 首次使用 3 问（称呼/在读的书/目标），替换硬编码画像 |

### P2 · v0.5+ 「内容与增长」

- 多书支持：第二本书（建议《通货膨胀的一部分》或《穷查理宝典》），课程 DSL 固化为 JSON schema。
- PDF/TXT 导入 → AI 生成概念草案 → 人工确认入库。
- 学习周报（基于真实 activity 数据）与分享卡片（传播面）。
- 移动端适配打磨（当前断点仅做了基本隐藏）。

### 明确不做（Non-goals）

- 不做通用 ChatGPT 替代品；不做社区/评论；不做多人协作；不做原生 App（先 web 到能用）。

## 6. 非功能需求

1. **性能**：首屏 JS < 300KB gzip；对话输入到首字节 < 1s（AI 模式取决于 API）。
2. **隐私**：所有学习数据存浏览器本地；API Key 不出浏览器（现状保持）；虚构画像明确标注。
3. **可靠性**：AI 请求失败必须无缝回退本地引擎（现有机制，回归测试覆盖）。
4. **可测试性**：SocraticEngine / storage / 意图路由补 Vitest 单测（P0 开始建立）。

## 7. 成功指标

- **北极星**：周完成概念数（用户真掌握了多少，而不是聊了多少）。
- 输入：对话首日留存 > 40%；单次会话 > 8 轮。
- 过程：四阶段完成率 > 60%；复习按期完成率 > 50%。
- 系统健康：AI 回退率 < 2%；空状态跳出率 < 30%。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 对话首页让结构感消失，用户迷路 | 卡片流承载进度；抽屉保留完整章节树 |
| AI 结构化输出不稳定（模型差异） | JSON 解析失败时降级为纯对话 + 本地评估兜底 |
| 单人开发节奏过长 | P0 严格裁剪到 5 个功能，两周一个可部署版本 |
| 关键词评估误判（本地模式） | P1 用 AI 评估替换；本地模式提示「AI 模式判定更准」 |
